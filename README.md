## 게임별 구현 범위

**블랙잭** — 히트·스탠드·더블다운·스플릿·보험. 딜러는 17에서 멈춥니다. 스플릿한 손의 21은 블랙잭이 아니라 일반 21로 정산합니다.

**룰렛** — 유럽식 단일 0(37칸). 숫자·색상·홀짝·구간·다스 베팅. 휠이 2단계로 감속하며 마커가 가리키는 숫자를 실시간으로 보여줍니다.

**바카라** — 플레이어·뱅커·타이. 3장째 뽑기 규칙을 표준 표대로 판정하고 뱅커 승리에 5% 커미션을 뗍니다.

**슬롯** — 같은 그림 3개는 그림별 4~50배, 2개는 1.5배. 🃏 조커는 와일드라 3개 판정과 2개 판정 양쪽에서 다른 그림을 대신합니다.

**포커류** — 7장 중 최적 5장 탐색, 오마하의 홀 2장 + 커뮤니티 3장 제약, 하이로우의 8-or-better 로우 판정.

## 포커 컴퓨터의 베팅 판단

홀덤 · 오마하 · 세븐 포커 · 파이브 카드 드로우 · 하이로우 다섯 종목에서 컴퓨터가 매 라운드 **폴드 · 체크 · 콜 · 레이즈**를 직접 고릅니다 (`src/pokerai.ts`).

- **승률 추정**: 자기 손과 지금까지 공개된 카드를 놓고, 남은 덱에서 상대 손과 앞으로 열릴 카드를 무작위로 채워 수백 번 돌려 이길 확률을 셉니다. 하이로우는 하이와 로우 승률을 평균 냅니다.
- **판단**: 그 승률을 팟 오즈(콜 금액 ÷ (팟 + 콜 금액))와 비교합니다. 승률이 팟 오즈보다 확실히 낮으면 폴드, 확실히 높으면 레이즈, 그 사이면 콜·체크. 낮은 확률로 세미 블러프를 섞습니다.
- **베팅 크기에 반응합니다.** 플랍에서 측정한 결과 — 콜 금액이 팟의 0.2배면 폴드 0% / 팟과 같으면 폴드 47% / 팟의 3배면 폴드 87%.
- **파이브 카드 드로우는 교환 장수를 읽습니다.** 교환 후 라운드에서 상대가 몇 장 바꿨는지를 조건으로 넣습니다. 보정값을 임의로 더하는 게 아니라, 무작위 손을 뽑아 "이 손이면 몇 장 바꿨을까"를 계산하고 실제 교환 장수와 다르면 그 표본을 버리는 방식(기각 표본)입니다. 그래서 1장만 바꾼 상대가 3장 바꾼 상대보다 강하게 잡힙니다.
- 양쪽이 넣은 돈을 따로 추적해 정산합니다. 라운드당 레이즈는 3회까지.

## 홍콩 마작

- 136장에 **꽃패 8장**(꽃 4 · 계절 4)을 더해 씁니다. 배패 때 일부가 나뉘고, 나머지는 산에 남아 게임 중에 뽑으면 옆으로 빼고 보충패를 가져옵니다(補花).
- 최소 번은 `⚙ 룰 설정`에서 1번(느슨) · 3번(표준) · 5번(엄격) 중 고릅니다. 자기 자리 번호와 같은 꽃패는 1번씩, 꽃 네 장 또는 계절 네 장을 모으면 2번씩 붙습니다.
- 부(符) 없이 번(番)만 세고, 점수는 기본점 × 2^번으로 오릅니다. 한도는 13번.
- 최소 **3번**을 넘겨야 화료할 수 있습니다. 한도 역은 번수와 무관하게 화료할 수 있습니다.
- 한도 역: 십삼요 · 대삼원 · 대사희 · 소사희 · 자일색 · 청요구 · 녹일색 · 십팔나한 · 구련보등 · 사암각 · 천화
- 일반 번: 청일색 7 · 소삼원 5 · 혼일색 3 · 대대화 3 · 혼요구 3 · 삼암각 2 · 칠대자 2 · 문전청자모 2 · 역패 · 자풍 · 장풍 · 평화 · 문전청 각 1
- 정산: 쯔모는 세 명이 각각, 론은 방총자가 세 명 몫을 전부 냅니다.
- 친이 이기면 연장, 지면 다음 자리로 넘어갑니다.

## 사천 마작 (혈전도저)

- 자패를 빼고 만수 · 통수 · 삭수 **108장**만 씁니다.
- **정결(定缺)**: 배패 뒤 만수·통수·삭수 중 하나를 직접 고릅니다. 그 종류를 전부 버려야 화료할 수 있고, 남아 있는 동안에는 그 종류만 버릴 수 있습니다. 대기패에서도 제외됩니다.
- **환삼장(換三張)**: 시작할 때 같은 종류 세 장을 옆자리로 넘깁니다.
- **혈전도저(血戰到底)**: 화료해도 국이 끝나지 않고 세 명이 화료할 때까지 이어집니다. 화료한 사람은 이후 지불에서 빠집니다. 내가 화료해 빠진 뒤의 진행은 자동으로 이어서 두고 결과를 보여줍니다.
- **치(吃) 없음**: 퐁과 깡만 부를 수 있습니다. 깡을 하면 산 뒤쪽에서 보충패를 가져옵니다.
- 같은 패 네 장을 두 쌍으로 세는 **용칠대자**를 완성으로 인정합니다.
- 번은 배수로 곱해집니다: 평화 1 · 대대화 2 · 청일색 4 · 칠대자 4 · 청대대 8 · 용칠대자 8 · 청칠대자 16 · 장대 16 · 청룡칠대자 32 · 십팔나한 64
- 근(根, 같은 패 네 장)마다 ×2, 자모 · 깡상화 · 창깡 · 해저포 각 ×2. 상한 64배.
- **과수(刮風下雨)**: 깡을 하는 순간 점수를 받습니다. 암깡·대명깡은 2점, 가깡은 1점.
- **차대각(査大叫)**: 유국이면 텐파이하지 못한 사람이 텐파이한 사람에게, 그 사람이 화료했을 때 받았을 점수만큼 물어줍니다. 정결을 못 끝낸 사람(화저)은 텐파이한 모두에게 물어줍니다. 결과 화면에 누가 텐파이·노텐·화저였는지 표시됩니다.
- **금구(門清)**: 한 번도 울지 않고 완성하면 배수 ×2.

## 게임 찾기

게임 탭에서 이름으로 검색하고 **전체 · 즐겨찾기 · 최근** 으로 거를 수 있습니다. 최근은 마지막으로 고른 게임을 맨 앞에 두고 그다음 최근에 플레이한 순서로 보여 줍니다(끝까지 하지 않고 열어만 봐도 들어갑니다). 목록에는 아직 안 되는 게임만 '준비 중'으로 표시합니다.

## 지갑과 기록

- 코인은 로컬(AsyncStorage)에 저장됩니다. 현금 환전은 없습니다.
- 최근 100판의 기록을 게임·결과·베팅·손익과 함께 저장합니다.
- 카테고리별 손익은 게임 이름으로 카테고리를 찾아 실제로 나눠 집계합니다.
- 수익률은 걸었던 코인 총액 대비 손익이고, 잔액 카드의 막대 그래프는 최근 여덟 판의 실제 손익입니다.
- 분석 화면 세 가지 — **게임별 손익**(게임마다 판수 · 승률 · 베팅 총액 · 손익 · 수익률), **베팅 등급별 수익률**(다섯 등급 전부, 안 해본 등급은 '기록 없음'), **전체 거래 내역**(전체 · 수익 · 손실 필터).

## 레벨과 미션

- **레벨**은 이기고 지는 것과 상관없이 누적 플레이 판수로만 오릅니다(`src/level.ts`). 레벨 n에서 다음 레벨까지 n×10판 — LV.1은 0판, LV.2는 10판, LV.3은 30판, LV.4는 60판, LV.5는 100판. 기록은 최근 100판만 남기므로 누적 판수는 따로 저장합니다.
- **오늘의 미션**은 하루 3판을 채우면 300 WC를 실제로 지급하고, 같은 날 두 번 주지 않도록 받은 날짜를 저장합니다.

## 한국 전통 — 화투

한국 전통 게임 여섯은 모두 화투 48장 한 벌을 같이 씁니다(`src/hwatu.ts`). 월마다 4장씩 12달, 종류별로 광 5 · 열끗 9 · 띠 10 · 피 24장이고, 띠는 홍단 3(1·2·3월) · 청단 3(6·9·10월) · 초단 3(4·5·7월) · 비띠 1(12월), 쌍피는 11월과 12월에 한 장씩입니다. 이 구성이 실제 화투와 같은지 테스트가 대조합니다.

### 섰다

1~10월 각 두 장, 모두 20장으로 두 장씩 받아 겨룹니다.

- 족보(높은 순): 삼팔광땡 · 일삼광땡 · 일팔광땡 → 장땡~1땡 → 알리(1·2) · 독사(1·4) · 구삥(1·9) · 장삥(1·10) · 장사(4·10) · 세륙(4·6) → 갑오(9끗)~한끗 → 망통(0끗)
- 광땡은 두 장 모두 **광**이어야 성립합니다. 광이 아닌 3·8은 그냥 한끗입니다.
- 특수 족보 **땡잡이(3·7) · 암행어사(4·7) · 멍텅구리구사(4·9)** 는 지역마다 쓰는 곳이 달라 준비 화면에서 끄고 켭니다. 기본은 꺼짐입니다. 제 역할을 못 하는 상황에서는 원래 끗수로 겨룹니다(예: 구사는 3끗).
- 컴퓨터는 남은 18장으로 만들 수 있는 상대 패 **153가지를 전부 세어** 이길 확률을 구하고, 그 확률과 팟 오즈를 비교해 죽기·받기·더 걸기를 고릅니다.

## 아이폰에서 쓸 때

- 뷰포트에 `viewport-fit=cover`를 붙이고 `env(safe-area-inset-*)` 값을 재서, 노치와 홈 인디케이터가 UI를 가리지 않게 헤더 위·탭바 아래에 여백을 줍니다.
- 사파리의 **밀어서 뒤로 가기**가 사이트를 나가는 대신 앱 안에서 한 단계 뒤로 갑니다(게임 → 준비 화면 → 목록 → 탭). 더 갈 곳이 없으면 막지 않고 그대로 나갑니다.
- 방문 기록은 **항상 한 칸만** 세워 둡니다. 화면을 옮길 때마다 쌓으면 사파리가 같은 페이지 안의 이동이 아니라 진짜 페이지 이동으로 취급해서, 뒤로 갈 때 흰 화면이 잠깐 보이고 느려집니다.
- 준비 화면에서 아래쪽을 보다가 게임에 들어갔다 나오면 **보던 위치로 되돌아옵니다**.

## 데이터

데이터는 **기기 안에만**(AsyncStorage/localStorage) 저장됩니다. 서버도 로그인도 없습니다.
깃허브는 코드를 두고 사이트를 띄우는 용도로만 씁니다 — 앱이 실행 중에 깃허브 API로 저장소에 데이터를 쓰지는 않습니다. 그러려면 쓰기 토큰이 공개 페이지 안에 들어가야 하고, 저장할 때마다 배포가 도는 구조가 되기 때문입니다.

기기를 옮기거나 보관하려면 설정의 **데이터 백업**을 씁니다.

- **파일로 내보내기** — 코인·누적 판수·난이도·기록·설정을 JSON 파일 하나로 저장합니다.
- **파일에서 가져오기** — `src/backup.ts`가 먼저 형식을 검사합니다. 깨진 파일, 다른 앱의 JSON, 더 새로운 버전에서 만든 파일은 거절하고 기존 데이터는 건드리지 않습니다. 검사를 통과해도 코인·판수·기록 수를 먼저 보여주고 확인을 받은 뒤에야 덮어씁니다. 읽지 못한 기록이 섞여 있으면 그 건수를 알려주고 건너뜁니다.

## 안정성

- 화면을 그리다가 에러가 나면 하얀 화면이 되는 대신 안내 화면이 뜨고 다시 시도할 수 있습니다(`AppErrorBoundary`). 렌더링 중 에러만 잡히고, 버튼을 누른 뒤 비동기로 나는 에러는 잡히지 않습니다.
- 저장된 기록이나 설정이 깨져 있어도 로딩 화면에서 멈추지 않고 기본값으로 시작합니다.
- 기록이 없을 때, 검색 결과가 없을 때 등 빈 화면 문구가 따로 있습니다.

## 개발

```sh
pnpm install
pnpm start        # Expo 개발 서버 — QR을 Expo Go로 스캔
pnpm typecheck    # TypeScript strict 검사
pnpm test         # 게임 규칙 자동 테스트
```

게임 규칙은 화면과 분리되어 `src/`에 있고, 각 모듈은 난수를 주입받을 수 있어 결정적으로 테스트됩니다. 규칙별 테스트는 `tests/`에 있습니다.

`main`에 푸시하면 GitHub Actions가 `expo export --platform web`으로 빌드해 GitHub Pages에 배포합니다.
